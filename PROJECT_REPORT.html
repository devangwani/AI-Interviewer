1. System Overview

The AI Interviewer is a full-stack web application that conducts automated, real-time job interviews. It streams audio for speech-to-text transcription, captures webcam frames for facial emotion analysis, dynamically generates questions via a large language model, and produces a multimodal report card scoring the candidate across communication, technical depth, confidence, and camera presence dimensions. It supports two user roles — Candidate and Recruiter — each with a separate dashboard.

Entry point for all users. Supports Google OAuth popup and email/password login or registration via Firebase. After authentication, calls POST /auth/login to upsert the MongoDB user record, stores the profile in Zustand, then routes to /select-role if the user has no role, otherwise to /dashboard.

Shown once after first login. Presents two role cards — Candidate and Recruiter. On click, calls PATCH /auth/me/role which sets the role without incrementing the switch counter. Redirects immediately if a role is already set.

Root post-login page. Acts as a role-based router: renders <RecruiterDashboard/> for recruiters, or the full candidate view otherwise. The candidate view has two sub-flows: self-directed interviews (configure role, type, difficulty, question count, optional resume upload) and recruiter-scheduled interviews (resume mandatory before start).

3.2 Hook — useWebRTC.js

Manages browser camera and microphone access. Attempts specific constraints (640×480) first, falls back to bare { video: true, audio: true }. Each attempt has a 20-second hard timeout via Promise.race. Returns true/false so callers can gate WebSocket connection. A useEffect assigns srcObject only when the active stream reference changes, preventing race conditions.

FunctionResponsibility
startMedia()Requests camera+mic with two-constraint retry, 20s timeout wrapper; returns true on success.
stopMedia()Stops all media tracks, clears refs, sets mediaReady = false.
getMediaWithTimeout(constraints)Internal helper — wraps getUserMedia in a race with a 20-second reject timer; cleans up orphaned streams.

3.3 Hook — useInterviewWS.js

Manages the single WebSocket connection to /api/v1/interviews/ws/{sessionId}. Handles three outbound streams (raw PCM audio bytes, base64 JPEG video frames every 3 seconds, JSON control messages) and four inbound message types. All callbacks are stored in refs to prevent stale-closure bugs on re-renders.

FunctionResponsibility
connect()Opens the WebSocket; dispatches inbound messages (ai_question, transcript, generating_report, interview_complete, error) to ref-stored callbacks.
startAudio(mediaStream)Creates a 16 kHz AudioContext, connects a ScriptProcessor node (4096-sample, mono), converts Float32 PCM to Int16, sends raw bytes over WebSocket.
startFrames(videoEl)Every 3 seconds: draws the video element onto a 224×224 canvas, encodes as base64 JPEG at 70% quality, sends as {"type":"video_frame","data":"..."}.
sendEndAnswer()Sends {"type":"end_answer"} to signal the server to close the current Deepgram connection and generate the next question or report.
disconnect()Stops audio, clears frame timer, closes the WebSocket.

3.4 Hook — useSpeechSynthesis.js

TTS via the browser Web Speech API. Voice selection prefers "Google US English", then any remote en-US voice, then any English voice. The onerror handler distinguishes intentional cancellations ("interrupted"/"canceled") from genuine errors — only genuine errors call onEnd() to advance the interview phase.

3.5 Hook — useVisibility.js (Proctoring)

Listens to document.visibilitychange and window.blur events; calls incrementTabSwitch() in Zustand whenever the candidate's window loses focus. Active only when enabled=true (disabled on loading and done phases).

4. Backend Services

4.1 Groq Service — groq_service.py

All LLM interactions use the llama-3.3-70b-versatile model via an async singleton client. A UUID nonce is injected into both the system prompt and user prompt on every call to defeat Groq's system-prompt-level response cache (preventing all candidates getting the same first question).

FunctionModel / TempResponsibility
generate_next_question(...)llama-3.3-70b / 0.9Dynamically generates one question using full conversation history and optional resume context. Applies interview-type-aware system prompts: behavioural → STAR-method only; HR → culture-fit only; technical/system_design → engineering depth. Difficulty sub-instructions calibrate question depth (beginner = definitions; intermediate = patterns; advanced = production-scale design).
evaluate_answer(...)llama-3.3-70b / 0.3Sends a Q&A pair and returns a JSON dict with score (0–10 float), strengths, improvements, and verdict ("strong"/"acceptable"/"weak").
generate_interview_questions(...)llama-3.3-70b / 0.7Legacy batch question generator (used only if the WebSocket engine is unavailable). Returns a list of N question strings.

4.2 Resume Service — resume_service.py

FunctionResponsibility
extract_text_from_pdf(file_bytes)Opens PDF from bytes using pdfplumber, concatenates text from all pages into a single string.
parse_resume(file_bytes)Calls extractor, truncates to 6,000 characters (token budget), sends to Groq (temp 0.1, JSON mode) with a parser prompt. Returns {"skills": [...], "projects": [{"name":..., "description":...}]}. Returns empty arrays on failure.

4.3 Emotion Analysis — emotion_analysis.py

Facial emotion recognition using a MobileNetV2 model fine-tuned on the RAF-DB dataset. Inference is offloaded to a thread-pool executor so it never blocks the async uvicorn event loop. An OpenCV Haar Cascade face detector gates each frame — frames with no detected face return None and are never counted in emotion statistics, preventing "Neutral" inflation from off-camera periods.

Class EmotionAnalyzer — methods

MethodResponsibility
load()Loads the .h5 model (Keras 3 compatibility patch applied), then loads the Haar Cascade. Idempotent.
analyze_frame(b64)Async; offloads inference to thread pool. Returns dict[label→prob] or None.
_has_face(frame)Runs detectMultiScale on full 224×224 greyscale frame (minNeighbors=3, minSize=40px). Returns True if any face found.
_preprocess(frame)Resize → BGR→RGB → divide by 255.0 → add batch dim → shape (1,224,224,3).
_run_inference(b64)Synchronous: decode → face check → preprocess → model.predict() → return all 7 softmax probabilities.

4.4 WebSocket Engine — routes/interview.py

The core real-time engine lives in the interview_websocket handler at /ws/{session_id}. It manages three parallel data streams within a single WebSocket connection.

Inbound from client
  • bytes → raw PCM Int16, 16 kHz mono → Deepgram STT (lazy-connected on first audio byte)
  • video_frame JSON → emotion_analyzer.analyze_frame() → accumulate to emotion_stats
  • end_answer JSON → close Deepgram, save transcript, generate next question or report
  • ping → respond with pong
Outbound to client
  • ai_question → question text + index + total
  • transcript → live STT chunk (is_final flag)
  • generating_report → triggers spinner
  • interview_complete → session_id + overall_score
  • error → error message string

After all questions are answered: the engine sends generating_report, builds presence_stats, calls generate_report_card(), persists to MongoDB via save_report_to_db(), then sends interview_complete.

5. Evaluation & Scoring System

All scoring happens inside evaluation_service.py via the generate_report_card() function, which feeds four evidence sources to llama-3.3-70b-versatile (temperature 0.2, max_tokens 4096, JSON mode).

5.1 Score Dimensions (all 0–10 scale)

ScoreDerived FromNotes
communication_scoreTranscript textSentence clarity, vocabulary richness, logical structure, completeness of verbal answers.
technical_scoreTranscript text + job roleTechnical accuracy per question, depth of knowledge, problem-solving approach, relevance to stated role.
confidence_scoreTranscript + emotion dataCombines verbal assertiveness signals with facial emotion distribution (Happiness/Neutral raises; Fear/Anger lowers).
visual_confidence_scoreCNN emotion data + presence rateNull if no camera data. Penalised if presence rate <70%. Set to "Insufficient data" if presence <40%.
overall_scoreAll four sub-scoresLLM-computed weighted average. Each sub-score includes a _breakdown array of criterion objects with met (bool), impact (e.g. "+2.0"), and an example note.

5.2 Camera Presence Rate

presence_rate = (frames_with_face / total_frames) × 100
ThresholdEffect on Report
≥ 70%No penalty. absence_warning = null.
40–69%Amber warning banner shown. Moderate penalty mandated on visual_confidence_score.
< 40%Red critical banner shown. Significant penalty mandated. visual_confidence_score may be set to "Insufficient data".
0 framesNo presence tracking available (legacy session). Treated as 100% — no penalty.

5.4 Academic Integrity Detection (Two-Layer)

Layer 1 — Keyword Detection: 14 regex patterns (case-insensitive) catch explicit AI self-disclosure: phrases like "I am a large language model", "as an AI", "my training data", named AI tools (ChatGPT, Claude, Gemini, Bard, Copilot), and "I cannot browse the internet". Each match is HIGH severity.

Layer 2 — Linguistic Naturalness Analysis: Five objective signals are computed per answer and summed into a suspicion score:

SignalSuspicion Points Added
Zero disfluencies ("um/uh/like") in ≥40-word answer+3
Disfluency rate <1% in ≥60-word answer+1
≥2 enumeration markers ("firstly/furthermore/additionally")+1 (or +2 if ≥3 markers)
AI hedging phrases ("plays a crucial role", "it is important to note")+1 per match, max +4
No personal anecdotes in ≥60-word answer+1
≥95% grammatically complete sentences across ≥4 sentences+1
naturalness = max(0, 10 − suspicion_pts × 2)

5.5 Integrity Risk Level Thresholds

Risk LevelTrigger Conditions
HIGHAny keyword hit, OR naturalness ≤ 2 on any single answer, OR multiple answers all at naturalness ≤ 4.
MEDIUMNaturalness ≤ 4 on any single answer, OR zero disfluencies detected across ≥2 answers.
LOWNaturalness 5–6 with some signals but no definitive evidence of AI use.
NONENaturalness ≥ 7 on all answers, zero signals detected.

The LLM is explicitly instructed: "Absence of explicit AI phrases does NOT mean the candidate is innocent." Integrity flags at HIGH risk must be reflected in both the verdict and the report summary.

6. Hire / Maybe / No-Hire Decision

The final verdict is an LLM holistic judgment combining all four evidence sources. No single numeric cutoff is hard-coded; instead, mandatory rules are enforced in the system prompt:

VerdictExpected ProfileBadge Colour
Strong HireHigh scores across all dimensions, natural speech, positive emotion, no integrity flags.Emerald
HireGood overall and technical scores, minor weaknesses, no significant flags.Green
MaybeMixed signals — moderate scores OR minor integrity / presence concerns.Amber
No HireLow technical/communication scores, HIGH integrity risk, or critical presence absence.Red

On JSON parse failure the fallback verdict defaults to "Maybe" and all scores to 5.0. Integrity risk is still computed deterministically from pre-computed flags (no LLM call needed).

Application Startup (main.py)

FastAPI app with @asynccontextmanager lifespan: connects MongoDB Atlas, loads MobileNetV2 emotion model (graceful skip if file missing), then registers three routers under /api/v1 (auth, interview, analysis). CORS middleware applied. Health check at GET /health.

StoreState managed

Critical Invariants (must never be reverted)
  • Deepgram lazy-connection: Deepgram must only connect on the first audio byte, not at WebSocket open — reverting causes 1011 timeout during TTS playback.
  • Groq UUID nonce in system prompt: Nonce must be in the system prompt (not just user prompt) to defeat Groq's system-prompt-level cache.
  • Haar Cascade on full 224×224 frame: Never halve the frame before cascade detection — shrinking to 112×112 causes faces to fall below the minimum detection size.
  • Emotion normalisation /255.0: The MobileNetV2 model was trained with rescale=1/255; using (x/127.5)-1 causes all predictions to collapse to Neutral.
  • WebSocket ws excluded from startup effect deps: The ws object is recreated on every render; including it causes infinite re-fires of the startup effect.
